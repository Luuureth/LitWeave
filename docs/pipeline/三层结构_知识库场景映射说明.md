# 三层结构：原子事件 -> 知识库规范事件 -> 跨模态场景映射

## 1. 目标

本方案不再直接做“文本事件 ↔ 视频事件”的硬一对一配对，而是采用三层结构：

1. **第 1 层：原始原子事件**  
   输入文件：`unified_events/unified_events.csv`  
   保留文本和视频两侧的细粒度事件、原文证据、路径信息。

2. **第 2 层：知识库规范事件**  
   输入文件：`知识库/事件知识库/事件知识库.csv`  
   每条记录作为一个规范事件节点（canonical event node），作为全局标准锚点。

3. **第 3 层：跨模态场景映射**  
   先让文本事件匹配到知识库事件，再让视频事件匹配到知识库事件。  
   如果文本和视频映射到同一个知识库事件，则认为它们属于同一叙事场景。

这样做的优点是：

- 避免文本与视频粒度天然不一致导致的一对一误配
- 使用知识库的标准事件名统一文本侧与视频侧表达
- 最终输出中仍保留前端需要的字段，例如：
  - `event_name`
  - `source_text`
  - `video_source_path`
  - `chapter_title`
  - `source_path`
  - `timeline_id`

## 4. 主要函数划分

### `load_atomic_events(unified_events_csv)`
读取原始原子事件表，校验必须字段。

### `load_kb_events(kb_events_csv)`
读取知识库事件表，校验必须字段。

### `build_atomic_event_repr(row)`
把原子事件拼成用于语义匹配的表示文本，综合：

- `action`
- `event_summary`
- `semantic_core`
- `characters`
- `location`
- `keywords`

### `build_kb_event_repr(row)`
把知识库规范事件拼成匹配表示，综合：

- `事件名`
- `event_aliases`
- `事件详情`
- `main_characters`
- `main_locations`
- `timeline_ref`

### `map_atomic_events_to_kb(events_df, kb_df, cfg)`
这是第 1 层到第 2 层的核心映射函数。  
每个原子事件会与知识库事件计算综合分数，得到：

- `kb_event_id`
- `kb_event_name`
- `kb_top1_score`
- `kb_topk_candidates`
- `timeline_id`

综合分数包含：

- 事件名相似度
- 事件详情相似度
- 人物重合度
- 地点重合度
- 可选的锚点事件轻微加权

### `build_kb_event_nodes_json(kb_df, events_with_kb, out_json)`
把知识库事件整理成标准节点，并统计当前有多少文本/视频事件映射到该规范事件。

### `build_cross_modal_scene_links(events_with_kb, out_json, cfg)`
这是第 2 层到第 3 层的核心映射函数。  
按 `kb_event_id` 聚合：

- 文本事件映射到同一个知识库事件
- 视频事件映射到同一个知识库事件
- 则生成一个跨模态场景链接 `cross_modal_scene_links.json`

### `export_atomic_events_json(events_with_kb, out_json)`
输出带知识库映射信息的原子事件 JSON，便于后续前端或调试。

### `run_kb_scene_mapping_pipeline(...)`
完整流水线入口。

## 6. 当前匹配思路

### 第一步：原子事件映射到知识库事件
对于每条原子事件，分别与每个知识库事件计算：

- 名称相似度
- 详情相似度
- 人物重合度
- 地点重合度

综合得到 `kb_top1_score`。

### 第二步：知识库事件桥接文本和视频
如果：

- 某些文本事件 -> `KBE016`
- 某些视频事件 -> `KBE016`

则说明它们都属于同一个规范事件，如：

- `听曲文宝玉悟禅机`

于是生成一条跨模态场景映射。

## 7. 与之前一对一方案的区别

### 之前
- 文本事件直接与视频事件对齐
- 很容易受粒度差异影响
- 视频切得比文本碎时，误配或漏配会很多

### 现在
- 文本先对齐到知识库
- 视频先对齐到知识库
- 再通过共享知识库事件建立联系

这样更适合《红楼梦》这种：

- 原著叙事块较长
- 电视剧镜头切分较细
- 改编时存在合并 / 拆分 / 顺序调整

## 8. 后续可继续增强的方向

### 1）增加场景内部聚类
现在主桥接对象还是原子事件。下一步可以继续在每个模态内部按：

- `source_id`
- `narrative_order`
- 共享人物 / 地点

聚成 `scene_event`，再映射到知识库，会更稳。

### 2）增加 LLM 审核层
目前知识库映射是规则 + 相似度方式。  
下一步可以对模糊样本再用 LLM 复核：

- 文本事件是否真属于该知识库事件
- 视频事件是否真属于该知识库事件

### 3）增加前端更友好的 summary 字段
例如在 `cross_modal_scene_links.json` 里再补：

- `scene_summary`
- `scene_keywords`
- `scene_title_for_ui`

## 11. 结论

这个方案的核心不是“文本和视频彼此强行找唯一对应”，而是：

**让文本和视频都先投影到统一的知识库规范事件空间，再通过规范事件建立叙事场景映射。**

这更适合《红楼梦》这类长篇文学作品与影视改编之间的跨模态对齐任务，也更有利于你后续做：

- 人物检索
- 地点检索
- 叙事时间线
- 前端场景浏览
