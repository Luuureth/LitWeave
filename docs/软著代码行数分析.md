## 五、软著提交建议

### 5.1 材料格式要求

软件著作权登记通常要求提交：

- **源程序前 30 页 + 后 30 页**
- 每页 **50 行**
- 合计 **3000 行** 源代码

本项目代码量充足，可从前端、后端中选取连续片段组成提交材料，无需额外凑行数。

### 5.2 推荐提交方案

#### 方案 A：全量源码提交（推荐）

- **范围：** `src/` + `server/` + 根目录配置文件
- **行数：** 约 8,705 行（有效行约 7,902 行）
- **优点：** 材料完整，余量充足，能体现前后端完整架构
- **适用：** 希望展示系统全貌时

#### 方案 B：核心业务代码提交

- **范围：** 排除 `src/app/components/ui/`（shadcn/ui 第三方组件库）
- **行数：** 约 3,595 行（有效行约 3,263 行）
- **优点：** 突出原创业务逻辑，减少第三方模板代码
- **适用：** 希望强调自研部分时
- **注意：** 有效行数余量约 263 行，仍达标但相对紧凑

### 5.3 关于 shadcn/ui 组件库

`src/app/components/ui/` 目录包含从 shadcn/ui 拷贝的通用 UI 组件（Button、Dialog、Sidebar 等），约 **5,110 行**。

- 该部分已集成在本项目源码树中，属于可运行系统的一部分
- 软著实践中，多数项目会将项目内全部源码一并提交
- 若希望突出原创性，可在方案 B 中排除该目录

### 5.4 提交前检查清单

- [ ] 已排除 `node_modules/`、`dist/`
- [ ] 已排除 `.env` 及含密钥的配置
- [ ] 已排除 JSON 数据文件（如 `display_events.json`）
- [ ] 源代码文件连续、完整，每页 50 行
- [ ] 页眉标注软件名称及版本号
- [ ] 前后 30 页来自同一版本代码

**技术栈：**

- 前端：React、TypeScript、Vite、Tailwind CSS、React Router
- 后端：Node.js、Express（或同类框架）、SQLite
- UI：shadcn/ui 组件库

## 七、统计方法说明

1. **总行数（含空行）：** 文件全部行数之和，含空行
2. **有效行数（非空行）：** 去除仅含空白字符的行后的行数
3. **统计工具：** 基于 PowerShell 脚本遍历项目目录逐文件计数
4. **统计基准：** 2026-07-01 当前工作区代码快照
